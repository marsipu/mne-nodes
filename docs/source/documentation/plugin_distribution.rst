Build and distribute a plugin
=============================

Start with the project generated by :doc:`function_importer`.
Check the distribution name, version, license, and dependencies in
``pyproject.toml``. Distribution names used by pip and module names used by
Python need not be identical.

Export a wheel and source archive
---------------------------------

In the plugin project's root folder, use Python's packaging tools:

.. code-block:: console

   python -m pip install build twine
   python -m build
   python -m twine check dist/*

Build produces a wheel and a source archive in ``dist``; this does not upload
them. Check that configuration, source, helpers, and resources are included.
Test an installation of the built wheel rather than only your editable source.
System tools such as FreeSurfer require separate installation instructions.

Share a wheel directly; the recipient installs it with
``python -m pip install <wheel-file>`` in the mne-nodes environment.
Entry-point discovery makes installed plugins available at startup or through
**Manage Plugins > Refresh**.

Publish only when ready
-----------------------

You can host an installable source project on GitHub and share its repository
URL for **Load Plugin from GitHub**. Publishing to PyPI is a separate, explicit
step using your packaging tools; the importer does not publish anything.
Use a unique distribution name and increase the version for each release.
Review licensing and exclude private recordings, credentials, and unrelated files
before any upload.

See :doc:`sharing` for pipeline exports, which are different from plugin releases.
